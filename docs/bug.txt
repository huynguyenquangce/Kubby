## Fixed

- [2026-08-19] Connecting to an untrusted kubeconfig could execute its credential
  helper or read an arbitrary local token/client-key path before the user saw any
  additional warning. Cause: client-go treats exec/auth-provider and file-backed
  authentication fields as active credential loaders, while Kubby passed the
  selected config directly into discovery. Fix: validate the selected context
  before transport creation and reject executable, file-backed, and proxy
  mechanisms until a dedicated high-risk approval UI exists. A successfully
  connected pasted kubeconfig is also cleared from the frontend state/editor so
  its credential lifetime does not extend through the dashboard session.

- [2026-08-19] Ollama could be configured with a remote endpoint while every UI
  surface still said it ran locally, and the AI evidence viewer did not display
  the same snapshot later sent by Ask. Cause: provider locality was inferred only
  from the provider name, and preview/send independently recollected live cluster
  evidence. Fix: accept Ollama only on loopback, validate again at dispatch, and
  bind one redacted evidence snapshot to the drawer thread for both inspection and
  every provider request. Redirect targets are revalidated so a loopback Ollama
  endpoint cannot forward the evidence off-machine, and AI POST redirects are
  never followed for any provider so keys/evidence cannot cross the chosen origin.

- [2026-08-19] Copy diagnostics could include a credential echoed in the last
  frontend error even though the report promised to contain no API key. Cause:
  provider/model fields used a key-free view, but the free-form last error bypassed
  the shared credential redactor. Fix: redact common credential shapes and the
  configured API key before including that error, with deterministic sentinel tests.

- [2026-08-19] The release build floor still selected Go 1.26.5 after four
  reachable standard-library advisories had been fixed in Go 1.26.6. Cause: the
  module toolchain directive and build documentation pinned the previous patch
  release. Fix: raise the enforced toolchain, build guide, diagnostics examples,
  and public version badge to Go 1.26.6, then require the release gates and binary
  to use that exact patched toolchain.

- [2026-08-12] The shared modal and confirmation dialog had no accessible name,
  so assistive technology announced only a generic dialog even though a visible
  title was present. Cause: both elements declared their ARIA dialog role but did
  not connect that role to the existing heading. Fix: add `aria-labelledby` for
  `modal-title` and `dialog-title`, with the Settings Playwright workflow pinning
  the shared modal contract.

- [2026-08-12] App connection/session lifecycle could race, duplicate context
  names overwrote one another, and exec/port-forward startup could complete after
  its drawer or cluster owner was gone. Cause: the cluster registry used display
  context names as identity and had no synchronization; bound methods re-read the
  mutable active pointer; port-forward was registered only after readiness; and
  streaming events lacked an end-to-end owner. Fix: stable connection IDs and an
  atomic locked transition now own add/switch/disconnect, every bound call keeps
  one cluster snapshot, pending port-forwards register a cancellable operation
  before I/O, exec/port-forward events carry exact session/connection ownership,
  and concurrent/deferred regression tests run under the Go race detector.

- [2026-08-11] Helm SDK v3.16.4 exposed install/upgrade to a reachable
  JSON-schema stack-exhaustion vulnerability. Cause: the dependency remained on
  a version older than the upstream 3.17.3 fix. Fix: upgrade to Helm v3.21.3 and
  its Kubernetes v0.36.2 dependency set, then make Go 1.26 the documented and
  module-enforced build baseline.

- [2026-08-11] Helm install preview and Install independently resolved a mutable
  repository URL/version, so a repository could return a benign chart for the
  preview and different bytes for the confirmed write. Cause: no artifact
  identity crossed the Wails boundary. Fix: SHA-256 fingerprint the resolved
  chart archive, require a successful preview of the exact form inputs before
  enabling Install, pass its digest to the backend, and refuse the write if the
  subsequently resolved archive differs.

- [2026-08-11] Private Helm repository credentials could remain in a world-readable
  `repositories.yaml`, and repository names containing path separators could
  escape Helm's intended cache naming. Cause: repo files were written with 0644
  and names were only checked for emptiness. Fix: restrict names to a conservative
  1–63 character identifier, use the same validation for cache reads/removals,
  and write plus chmod repository configuration to 0600.

- [2026-08-11] AI evidence could include raw Secret `data`/`stringData`, Pod
  literal environment values, and common credential strings from logs/events.
  Cause: `DiagnosticContext` truncated but otherwise forwarded `GetYAML`, events,
  and logs verbatim. Fix: structurally redact Secret values and all literal
  `env[].value` fields before YAML truncation, filter common Bearer/key-value
  credential shapes from free text, and pin each path with unique-sentinel tests.

- [2026-08-11] Opening AI Settings returned the stored API key to the WebView
  and repopulated the password input, contrary to its write-only label; a custom
  hosted endpoint could also receive that credential over plain HTTP. Cause:
  `GetAIConfig` exposed the persistence model directly and provider URL checks
  accepted both schemes equally. Fix: expose a key-free view model with only a
  `hasApiKey` flag, preserve a blank key server-side for the same provider,
  re-apply 0600 after every write, require HTTPS except for loopback, and bound
  AI response bodies to 2 MiB.

- [2026-08-11] Pause/resume, cordon/uncordon, YAML Save, and Helm Test could
  mutate the active cluster immediately, despite the global confirmation
  invariant. Cause: these handlers called their Wails write bindings directly
  while older actions each implemented confirmation ad hoc. Fix: route the four
  paths through a testable confirmation boundary, identify the exact cluster and
  resource in the prompt, summarize YAML line changes, and re-check request
  ownership after confirmation so Cancel performs zero backend calls and a
  cluster/resource switch cannot redirect an approved action.

- [2026-08-11] A port-forward kept running after its resource drawer closed but

- [2026-08-11] Cancel, the title-bar X, and backdrop clicks stopped closing every

- [2026-08-11] A slow Helm/chart response could write release A's values or chart

- [2026-07-30] The Quota cell stayed clipped to "5 quota · …" after a fix that looked

- [2026-07-30] Right-sizing showed the same fact as two different numbers: a tile said

  MemReservedPct / MemUsedPct, computed once; advice and the tiles both read them.
- [2026-07-30] Right-sizing: the "requested" bar read as an empty track, so the hero

  Cause behind the cause: wrong FORM. Per the dataviz guidance, a ratio against a

- [2026-07-30] Right-sizing: the hero bars were ~97% empty and told the reader nothing.
  Cause: the bars were scaled to the cluster's *allocatable* capacity. On a 10-core

  sliver of a 1500px bar, so the requested-vs-used comparison — the entire point of

  max(requested, used), so they fill the width and the ratio is the shape; the

- [2026-07-30] Right-sizing table showed "9Mi of 0Mi" and "34m of 1m".
  Cause: the cell always printed "used of requested", including when nothing was
  requested — a ratio against zero, presented as a fact. Fix: "9Mi used · no request"
  when there is no request, "—" when there is neither request nor usage, and
  "35m used · 1m req" otherwise. Also the Quota column was truncating to

- [2026-07-30] Right-sizing: header row shifted one column off its data, and the whole
  page grew a horizontal scrollbar.
  Cause: two selectors in main.js decorate every table under `#content .view` with a
  bulk-select column plus Age + Actions, excluding specific view *ids*. The new view
  was not in either exclusion list, so both its tables got three phantom header
  cells — the header shifted left of the body and the extra width overflowed the
  window. Same root cause as the ResourceQuotas column shift below; an id-based
  opt-out means every new non-list view must remember to edit two selectors.
  Fix: opt out by markup instead — `table.plain` is skipped, and both selectors now
  say `table:not(.plain)`. Recorded as an invariant in ARCHITECTURE.md, because the
  next new view will hit it otherwise. Also: sizing tables are `table-layout: fixed`
  with percentage column widths inside an `overflow-x: auto` wrapper, so a long
  finding scrolls the table rather than the page.
- [2026-07-30] Right-sizing showed "NOT DECLARED 45" on a cluster with 22 containers.
  Cause: the tile summed noCpuRequest + noMemRequest + noMemLimit. Those overlap —
  one container declaring nothing counts in all three — so the sum can exceed the
  number of containers and means nothing. Fix: NamespaceSizing.Undeclared counts
  containers missing at least ONE of the three, displayed as "18 of 22"; the three
  individual counts stay only in the advice lines, where each names a specific fix.
  The view was also redesigned in the same pass: six equal number tiles replaced by
  one bar per resource (fill = used, tick = requested, full width = allocatable),
  because the comparison is the content and the tiles made the reader do the
  arithmetic themselves.
- [2026-08-11] A slow list or drawer response could repaint a newer namespace,
  resource, or cluster; most dangerously, the singleton YAML editor could show
  resource A while the drawer header showed B, and Save trusted the identity in
  that stale YAML. Cause: async Wails responses wrote shared DOM/editor state with
  no common connection/view/drawer ownership generation; the backend accepted the
  YAML's own kind, namespace, and name as its update target. Fix: exact ownership
  scopes now invalidate stale success and error callbacks, actionable rows clear
  when a new view load begins, YAML Save stays disabled until the current drawer

  identity mismatch. Deferred-promise JS tests and Go precondition tests pin the

- [2026-07-29] Every diff rendered double-spaced — a blank line between each line of
  the diff, so it was twice as tall and needed twice the scrolling.
  Cause: the line spans are `display: block` (so they already break), but the code
  joined them with '\n' AND the containers (.yaml-diff, .pv-diff, .diff-view) are
  `white-space: pre|pre-wrap`, which preserves that newline as its own empty line.
  Pre-existing in the drawer's YAML → Diff tab and in all three Helm diffs; only
  noticed when the dry-run preview made diffs long enough to be obvious. Fix: join
  with '' in both renderers, with the reason recorded next to the code — the block
  display and the empty separator have to stay together.
  Also: .pv switched from `height: 52vh` to `max-height`, so an all-unchanged preview
  no longer sits in a half-empty box.
- [2026-07-29] Editing YAML: Tab jumped out of the box instead of indenting, and a
  failed apply said "document 3 failed" with no way to find document 3.
  Cause: the editor was a plain <textarea>. A textarea cannot indent (Tab is focus
  navigation), has no line numbers, and gives no syntax feedback — for indentation-
  sensitive text that is a functional gap, not a cosmetic one. Fix: one shared
  CodeMirror editor (frontend/src/editor.js) behind every YAML box, with a gutter
  marker placed on the failing document's first line after an apply error.
  Two regressions came with it and were fixed in the same change, both from the same
  root fact — CodeMirror's editable element is a contenteditable <div>, not a
  <textarea>: (a) the global Enter handler excluded only TEXTAREA, so Enter inside the
  Import YAML editor would have submitted the modal and applied a half-typed manifest;
  (b) Escape closed the modal even when CodeMirror needed it (its search panel). The
  handler now excludes .cm-editor and returns early on e.defaultPrevented.
- [2026-07-29] "+ Create" on a name that already existed silently updated the object,
  with nothing to distinguish that from creating it.
  Cause: Create and Import YAML both end in a server-side apply, which is
  create-or-update by design — correct behaviour, but invisible before the fact.
  Fix: a dry-run Preview (DryRun: All, diffed against the live object) on both flows,
  labelling each document create / update / unchanged before anything is written.
  Worth knowing: the preview immediately exposed a second surprise nobody would have
  predicted client-side — changing a Service's port from 8081 to 9090 does not replace
  the port, because the ports list merges by port+protocol, so the object ends up with
  both.
- [2026-07-29] Actions the connected token could not perform were offered anyway: you
  clicked Delete, confirmed the dialog, and only then got a 403.
  Cause: nothing ever asked the cluster what the identity was allowed to do.
  Fix: SelfSubjectAccessReview per kind+namespace (internal/k8sclient/access.go),
  cached per connection, disabling (not hiding) what is not permitted and putting the
  reason in the tooltip. Pod subresources are probed separately because a role granting
  `pods` says nothing about `pods/log` or `pods/exec`. Deliberate design point recorded
  because it is easy to "fix" the wrong way: an unanswerable probe counts as ALLOWED —
  greying out the UI of a user who does have access would be worse than the 403 this
  replaced, and the apiserver is still the real enforcer.
- [2026-07-28] The app stalled for a second or more on every namespace change.
  Three compounding causes. (1) client-go's default client-side rate limiter is QPS 5 /
  Burst 10, so past the burst every further request *sleeps* — one sidebar refresh fans
  out to ~25 lists, and client-go was logging "Waited for 1.1s due to client-side
  throttling". (2) Counts were one bound call per kind, ~25 Wails round-trips, each
  serialising every object of that kind just so JS could take `.length` (a cluster-wide
  Secret list transfers every value to report a number). (3) All of them were refired on
  a namespace change, including cluster-scoped kinds whose counts cannot change.
  Fix: QPS 50 / Burst 100; one `SidebarCounts` call fanning out concurrently in Go with
  metadata-only lists where only a number is shown; `includeCluster=false` on a namespace
  change; and a request-generation guard so a slow reply can't repaint over a newer one.
  Measured on a one-node kind cluster: 930ms → 73ms. NamespaceSummary (the namespace
  drawer) got the same treatment.
- [2026-07-28] Command palette found nothing for "virtualservice" on an Istio cluster.
  Cause: the palette offers "Go to <section>" for each entry in PAGE_TITLES, and sections
  existed only for hard-coded built-in kinds. Global search had the same gap plus more —
  it covered 10 kinds and missed Jobs, CronJobs, PVCs, ServiceAccounts, PVs,
  StorageClasses, all of RBAC, quotas and every custom resource.
  Fix: `custom.go` turns each CRD-defined kind into a real section (registered in
  PAGE_TITLES, so the palette picks it up for free) with a generic list table that opens
  the usual drawer; `SearchResources` now covers every kind the UI has a section for,
  custom resources included, fanned out concurrently with metadata-only lists — broader
  *and* faster than the old sequential version. Matched Pods get their error flag
  resolved afterwards, which metadata lists cannot supply.
- [2026-07-28] Overview → Node usage rendered as blank white lines, no bars visible.
  Cause: `.nm-bar` / `.nm-bar-fill` were inline `<span>`s. The grid blockified the track,
  but the fill kept `display:inline`, so `height:100%` and `width:N%` were both ignored
  and it painted nothing. Fix: every bar element is explicitly `display:block`; the panel
  was also redesigned (responsive card grid, cluster totals in the header, thresholds at
  70/90%, clickable node names, cores/GiB instead of raw milli/Mi).
- [2026-07-28] "Import YAML" refused Istio manifests, reporting a missing/unsupported kind.
  Two separate causes. (1) The manifest had two documents with no `---` between them, so
  YAML parsed it as one document with duplicate keys and kept only the last — the Gateway
  vanished silently, with no error. (2) Kind→resource mapping came from a static
  `gvrByKind` table listing only built-in kinds, so any CRD kind was rejected outright.
  Fix: `apiindex.go` resolves apiVersion+kind against live API discovery (cached, refreshed
  once on a miss so a newly installed CRD is found), and `checkMissingSeparator` names the
  missing-`---` case instead of applying half the file. Apply is now a server-side apply
  with a per-document report, and strips server-owned metadata so `kubectl get -o yaml`
  output can be pasted as-is.
- [2026-07-28] Traffic flow was empty on an Istio cluster (no Ingress objects exist there).
  Fix: `istioflow.go` renders Istio Gateway + VirtualService in the same Route→Service→Pods
  lanes, badged `Gateway`, with the VirtualService named on each route it created. Adds two
  Istio-specific checks: a Gateway selector matching no ingress-gateway Pod, and a
  `credentialName` TLS secret missing from the ingress gateway's namespace (not the app's).
- [2026-07-27] Traffic flow: a deleted Ingress kept showing.
  Cause: an Ingress held by a finalizer stays in the API with a deletionTimestamp,
  and NetworkTopology listed it as live routing. Fix: netflow.go skips objects with
  a DeletionTimestamp; loadTraffic() also drops responses from superseded requests
  so a slow reply can't repaint stale topology.
- [2026-07-27] ResourceQuotas / LimitRanges: the Age and Actions columns were broken.
  Cause: main.js appends Age + Actions headers to every list table, but those two
  cellsFns (and CRDs) never emitted an age cell, so every column shifted one left.
  Fix: emit the age cell; padRowToHeader() backfills short rows as a safety net.
  Also: the quota summary was built by ranging a Go map, so its order reshuffled on
  every refresh — now sorted, and rendered as chips that flag any resource at its limit.
- [2026-08-11] Noisy live logs progressively froze the drawer.
  Cause: every line crossed the Wails bridge as its own event, appended with an
  allocating `slice(-5000)`, filtered/joined all retained lines, and replaced the
  whole `<pre>` immediately. Work therefore grew with both log rate and retained
  history; late events also had no Pod/container owner. Fix: backend batches of up
  to 64 lines/40 ms, an owned stream ID on batch/error events, a 5,000-line ring
  buffer, and animation-frame render coalescing.
- [2026-08-14] Pod logs still opened slowly and a sufficiently noisy Follow stream
  could continue to fall behind after the first batching fix. Three remaining
  causes compounded: opening a Pod eagerly loaded hidden Details/YAML/Terminal
  tabs (including two identical Pod container requests); a full 64-line batch
  emitted immediately, so Wails' asynchronous WebView queue still had no rate
  bound; and every animation frame still replaced all 5,000 retained lines in the
  `<pre>`. Fix: drawer tabs now load only on first selection and share one owned
  container request; the backend emits at most one 512-line batch per 40 ms and
  applies reader backpressure between ticks; unfiltered Follow appends text-node
  chunks and removes only the oldest chunks. Static loads and filter changes keep
  the deliberate full rebuild because they replace the visible result set.
- [2026-08-11] Large YAML and Helm diffs could freeze or exhaust the WebView.
  Cause: `lineDiff` retained an `(n+1)*(m+1)` Int32 LCS matrix; two 10,000-line
  documents implied roughly 382 MiB before render costs. Fix: a line-oriented
  Myers bisect diff with O(n+m) frontier memory and a deterministic work-budget
  fallback that remains correct but may show a whole block as replaced.
- [2026-08-11] Overview multiplied bridge/API work on every live refresh.
  Cause: JavaScript independently called seven App methods; Node capacity listed
  Nodes a second time, and the 5-second loop also refreshed every sidebar kind.
  Fix: one `OverviewSnapshot` bound call with bounded Go fan-out, shared Node/Pod
  lists, metadata-only counts, partial-section warnings, and a 30-second sidebar
  live TTL. Synthetic 10,000-Pod backend processing measured about 33 ms/op and
  54.6 MB/op on the development machine.

  hiding the node signals needed for debugging. Cause: both sections rendered the

  remains the single capacity owner; the lower section now derives readiness,
