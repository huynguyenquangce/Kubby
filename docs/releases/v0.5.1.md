# Kubby v0.5.1

This maintenance preview improves log-follow lifecycle, scheduling diagnosis and
credential handling. It keeps the Health checks, Why Pending and Cleanup features
introduced in v0.5.0.

## Install

Download `kubby-windows-amd64-setup.exe` and run it. It installs Kubby for the
current user without an administrator prompt, adds Start Menu and Desktop
shortcuts, and can be removed from **Settings → Apps**; your settings are kept.
To upgrade, close Kubby and run the newer installer. The portable
`kubby-windows-amd64.exe` remains available, and each asset has a `.sha256`
checksum.

## Fixes

- Why Pending leads with known missing, terminating, Lost or Immediate-Pending
  PVC blockers even when a node has enough capacity. An unreadable StorageClass
  is explicitly unknown, not assumed Immediate; WaitForFirstConsumer remains
  expected Pending state.
- Deployment rollback retries concurrent controller updates while preserving unrelated fields and refuses a replacement UID.
- Follow stops when its stream ends and retains the final log lines. Delayed old
  stops and completion events cannot cancel a replacement stream.
- AI provider errors redact the configured key and credential-shaped text before
  reaching the UI. Copy answer uses the native clipboard bridge and checks its
  result.
- Incident Markdown exports redact credential-shaped evidence. Log and incident
  exports default to private file permissions, including existing destinations.
- Helm defaults use the same bounded, cancellable, credential-aware acquisition
  path as preview/install. External chart links accept HTTP(S) only and reject
  embedded credentials.
- Resource table filtering/selection/sorting, stream cancellation and repository
  transport also include the preceding source fixes captured in docs/bug.txt.

## Verification

The release preparation includes provider HTTP contracts, strict browser mocks,
confirmation/preview/stale-owner regressions and both zoom matrices. A uniquely
named disposable kind namespace exercises real apply/scale/pause/restart/rollback,
log streaming, PTY/resize, Redis port-forward traffic, denied RBAC and the Helm
preview/install/upgrade/rollback/test/uninstall lifecycle, then is deleted.
See [release readiness](../RELEASE-READINESS.md) for final counts, artifact hash,
scanner results and remaining gates. Browser and backend results do not replace
the native Windows check of the final release executable.

## Preview limitations

- Windows x86-64 requires WebView2. This build remains unsigned; distribute it as
  a prerelease and expect SmartScreen publisher prompts.
- Kubeconfigs must use embedded tokens/certificates. Exec/auth-provider plugins,
  token/certificate/key file references and kubeconfig proxies are rejected
  before connecting. This particularly affects some cloud-generated configs.
- AI provider contract tests use synthetic loopback endpoints; real hosted
  provider availability and model behavior are not guaranteed by these tests.
- Private-repository transport has automated synthetic coverage; external
  repository availability and native credential-free rendering remain checks.
- Native Windows startup, focus/zoom, clipboard/file dialogs, ANSI/PTY input and
  tunnel manager behavior must be recorded before publication.
- Typed resource lists other than Pods/custom resources remain unpaged. The
  scheduling/policy checks model API evidence rather than a live scheduler trace
  or CNI packet enforcement.
- Final govulncheck still flags GO-2026-5932 in linked `golang.org/x/crypto/openpgp`; upstream provides no fixed version. Kubby disables the Helm provenance-verification path and uses reviewed SHA-256 chart digests; a regression test guards this boundary. The scanner therefore remains non-zero.
- Patched Go 1.26.9, x/net 0.60.0 and ORAS 2.6.2 remove the other 11 advisory findings from the initial scan.
