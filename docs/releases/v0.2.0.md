# Kubby v0.2.0

Kubby's second public preview focuses on a clearer cluster overview, safer
multi-cluster workflows, a real Pod terminal, and reproducible UI coverage across
desktop sizes and WebView zoom levels.

## Highlights

- Explore the complete cluster as Entry point → Service → Workload → Pod in the
  new Cluster Structure view, including internal Services and unexposed workloads.
- Use the redesigned Overview for a compact cluster pulse, node health, attention
  items, top consumers, and recent events, with consistent bundled Inter typography.
- Open a Pod terminal that auto-attaches, prefers Bash when available, supports raw
  shell keys and ANSI output, and propagates terminal resize through a PTY.
- Keep selected port forwards running after closing a drawer and manage every live
  tunnel from the global top-bar manager.
- Work more safely across clusters: stable connection identities, stale-response
  ownership checks, synchronized session cleanup, and resource-bound write approval
  prevent late work from crossing cluster or drawer boundaries.
- Use the unified Helm workspace for releases, catalog search, repositories, live
  resource health, history, tests, rollback, uninstall, and digest-bound install or
  revision-bound upgrade previews.
- Navigate reliably from narrow windows through 80–200% zoom with off-canvas
  navigation, responsive drawers and modals, and deterministic Playwright coverage.
- Follow high-volume logs with bounded buffering and coalesced rendering rather than
  one full repaint per incoming line.

## Security and safety

- Helm is upgraded to v3.21.3 and Kubernetes libraries to v0.36.2.
- AI evidence redacts Secret values, literal environment values, and common
  credential shapes before preview or transmission. The reviewed snapshot is reused
  exactly for its thread; Ollama is loopback-only, hosted endpoints require HTTPS,
  and AI POST redirects are not followed.
- Private Helm repository configuration and AI settings request mode 0600 where
  supported and remain under the current user's configuration profile.
- YAML Save, pause/resume, cordon/uncordon, and Helm Test now use the shared explicit
  confirmation boundary and re-check resource ownership before dispatch.
- Copy diagnostics redacts credential-shaped values and the configured AI key from
  the last shown error, while warning that server/resource details still need review.
- The release uses Go 1.26.6, which fixes reachable issues in URL parsing, TLS
  post-handshake handling, ASN.1 recursion depth, and IDNA validation reported
  against Go 1.26.5.

## Download

Download `kubby-windows-amd64.exe` and its `.sha256` file from the assets below.
Windows 11 normally already includes the required WebView2 runtime. Kubby needs a
kubeconfig with the permissions for the operations you choose to perform.

## Preview limitations

- The Windows executable is not code-signed yet, so Windows SmartScreen may ask you
  to confirm the publisher before first launch.
- This release publishes a Windows x86-64 binary only; source remains portable.
- Windows does not implement POSIX mode 0600; credential files rely on the current
  user's inherited profile ACL rather than an application-created owner-only DACL.
- Permission pre-gating covers resource and Pod-subresource actions. Import YAML,
  parts of Drain, and Helm actions still defer authorization to the API server.
- Kubeconfigs using exec/auth-provider credential plugins, token/certificate/key
  file references, or a kubeconfig-defined proxy are rejected in this preview.
  Use embedded credential data until Kubby can present a separate high-risk
  approval before running commands or reading local credential files.
- `govulncheck` reports GO-2026-5932 in Helm v3's linked legacy OpenPGP package,
  for which upstream provides no fixed version. Kubby explicitly disables that
  verification path and binds reviewed Helm installs to the previewed chart's
  SHA-256 digest; a regression test keeps OpenPGP verification disabled.
- Helm, Artifact Hub, and hosted AI providers require outbound network access.
