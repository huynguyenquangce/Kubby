# Kubby v0.3.0

Kubby's third public preview focuses on evidence-first incident investigation,
safer asynchronous workflows, faster cluster exploration, stronger remote-input
boundaries, and reliable operation through narrow windows and heavy WebView zoom.

## Highlights

- Investigate failing workloads through the new Incident Studio, with ranked
  findings, bounded evidence, a timestamped timeline, related resources, safe
  hand-offs to existing workflows, recovery watching, and Markdown export.
- Open resource Details through one connection-owned snapshot with concurrent
  backend fan-out, best-effort section errors, and exact cancellation when its
  drawer closes or changes ownership.
- Search cluster resources through a short-lived metadata index and reuse
  concurrent cold loads instead of rediscovering and relisting on every query.
- Use explicit Terminal Copy and Paste controls, standard terminal shortcuts,
  right-click clipboard behavior, ordered PTY input, and Bash-first auto-attach.
- Navigate all 60 discoverable Custom Resource kinds from the sidebar, including
  narrow off-canvas layouts, without clipping later entries.
- Return to Overview from the Kubby brand and use a compact command trigger and
  resource toolbar that preserve keyboard focus and accessible names.
- Keep the Pod Terminal usable at the low-height CSS viewports produced by
  175–200% desktop zoom; its controls, PTY, and status remain drawer-owned.

## Safety, security, and correctness

- Server-side Apply no longer force-takes managed fields; conflicts are surfaced
  for an explicit user decision instead of silently replacing another manager.
- Artifact Hub and Helm HTTP responses are size-bounded, redirects are validated,
  HTTPS downgrades are rejected, credentials remain origin-scoped, and errors do
  not echo query-bearing source URLs.
- Late drawer, modal, Settings, Welcome, Helm, AI, delete, and export responses
  must prove exact UI ownership before changing or closing a newer surface.
- Permission probes match the Kubernetes request actually sent, including
  `update` for YAML Save and the Scale subresource for workload scaling.
- Diagnostics and AI evidence retain credential redaction and never include the
  configured AI key or pasted kubeconfig content.

## Performance and release quality

- xterm and FitAddon load only when Terminal is opened, keeping the production
  entry chunk substantially smaller for users who never start an exec session.
- CI now gates Go formatting, tests, build and vet; the complete Chromium suite;
  stale Wails bindings; and a checksummed Windows Wails build.
- Responsive automation covers CSS viewport equivalents for 80–200% zoom on
  1366×768 and 1920×1080, a 390 px mobile shell, two-axis overlay bounds,
  content-owned wide-table scrolling, and the 60-kind Custom Resources limit.
- Stable visual baselines cover the compact command bar, light/dark Overview,
  Cluster Structure, Pod Terminal, and Incident Studio.

## Download

Download `kubby-windows-amd64.exe` and
`kubby-windows-amd64.exe.sha256` from the assets below. Windows 11 normally
already includes the required WebView2 runtime. Kubby needs a kubeconfig with the
permissions for the read and write operations you choose to perform.

## Preview limitations

- The Windows executable is not code-signed, so Windows SmartScreen may ask you
  to confirm the publisher before first launch.
- This prerelease publishes a Windows x86-64 binary only; source remains portable.
- Browser automation cannot prove native WebView2 clipboard, focus/paint, file
  dialog, ANSI rendering, or PTY resize behavior; those remain native release
  checks.
- Large Kubernetes API lists and large resource-table DOMs are not yet paginated
  or virtualized.
- Permission pre-gating still cannot model every dynamic multi-resource plan;
  the API server remains authoritative after explicit confirmation.
- `govulncheck` reports GO-2026-5932 in Helm v3's linked legacy OpenPGP
  package, for which upstream provides no fixed version. Kubby does not expose
  that provenance-verification path, explicitly keeps `ChartPathOptions.Verify`
  disabled, and instead binds reviewed Helm writes to SHA-256 preview digests;
  a regression test pins this boundary.
- Helm, Artifact Hub, and hosted AI providers require outbound network access.
